# 프로젝트 자료 수집 업데이트

## Windows 적용 순서

기존 Plus·마크다운 업데이트가 적용된 앱을 기준으로 한다. 실행 중인 개발 서버를 Ctrl+C로 종료하고 업데이트 ZIP 내용을 기존 package.json 폴더에 덮어쓴다. 현재 Supabase 프로젝트의 SQL Editor에서 다음 두 파일을 각각 열어 **한 번씩** 실행한다. 기존 프로젝트·세션·채팅·비공개 버킷 마이그레이션은 이미 적용되어 있어야 한다.

1. `supabase/migrations/202611190001_sources.sql` — project_materials와 RLS, 자료 등록·목록·조회·자동 수집 RPC, 완료 답변 출처 보관 트리거를 생성한다. 기존 완료 답변의 출처 메타데이터도 프로젝트별로 읽어 자료함에 반영한다.
2. `supabase/migrations/202611190002_material_storage.sql` — 기존 비공개 research-files 버킷에 본인 프로젝트 PDF의 읽기·등록 정책을 추가한다. 공개 버킷 전환이나 서비스 역할 키는 필요 없다.

그다음 앱 폴더의 PowerShell에서 실행한다.

```powershell
npm ci
npm run dev:plus
```

기존 .env.local과 ChatGPT 플랜 연결을 사용한다. 이 업데이트는 수집 본문을 모델 입력에 자동으로 추가하지 않는다.

## 확인

- 기존 메인 세션에서 **프로젝트 자료함**을 펼친다. URL을 등록해 제목·출처 링크·본문을 확인한다. 접근 또는 추출에 실패하면 URL과 사유가 남으며 **본문 가져오기**로 재시도할 수 있다.
- PDF 파일(최대 8 MiB)을 등록한다. 원본은 비공개 버킷에 보관하고, 텍스트가 있는 PDF는 페이지 순서대로 본문을 추출한다. 스캔·암호화 파일은 원본 다운로드와 실패 사유를 제공한다. OCR은 포함하지 않는다.
- 텍스트는 제목과 본문을 붙여넣어 등록한다. 자료를 열고 F5를 누르면 프로젝트와 열린 자료가 복원된다. 다른 프로젝트에서는 그 프로젝트에 등록한 자료만 보인다.
- 검색 답변이 완료되면 인용과 검색 후보 링크를 같은 트랜잭션에서 보관한다. 목록의 **답변 인용**과 **검색 후보**는 독립 표식이며 같은 URL에 둘 다 표시될 수 있다. 원래 답변별 근거는 chat_replies.metadata에 보존한다.

## 처리 범위

같은 프로젝트 안에서 URL은 스킴·호스트·표준 포트·조각 식별자를 정규화해 중복 등록을 방지한다. 경로·쿼리는 유지한다. 텍스트와 PDF는 각각 원문과 파일의 SHA-256으로 중복을 판정한다. 이미 확보한 본문은 중복 등록 실패로 덮어쓰지 않는다.

프로젝트 화면이 열리면 보관된 검색 링크의 본문 수집을 재개한다. 답변 인용을 우선하며 자동 수집은 프로젝트당 최근 24시간 최대 25개 자료로 제한한다. 미처리 링크도 목록에서 바로 열 수 있다. 사용자 수동 수집은 즉시 실행한다. 접근 가능한 HTML·일반 텍스트·PDF를 지원하며 사이트 정책, 사설 주소, 리디렉션, 시간·크기 한도를 검사한다. 로그인·유료 접근 장벽이나 스크립트 실행이 필요한 페이지는 본문을 확보하지 못할 수 있다. 업로드 PDF 분석 한도는 400페이지·추출 텍스트 75만 자이며 URL 수집에도 8 MiB 한도가 적용된다.

## 검증 환경

로컬 Chromium과 PGlite로 URL·PDF·텍스트 등록 및 재열람, 원본 PDF 다운로드, 실패 상태 보존을 검증했다. URL 브라우저 검사는 DNS/HTTP 테스트 응답으로 사이트 본문과 robots 차단을 재현했다. PDF 파서와 데이터베이스 마이그레이션·RPC는 실제 코드를 실행했다. mock의 원본 PDF는 로컬 파일에 저장된다. 운영 Supabase Storage 업로드와 개인 PC에서의 실제 사이트별 수집 여부는 두 SQL 적용 후 확인한다.

두 추가 SQL은 PostgreSQL 17에서도 기존 완료 답변이 들어 있는 테스트 DB에 순서대로 적용했다. 동일 URL의 인용·후보가 한 자료에 함께 표시되는지, 다른 사용자로 전환하면 자료 및 PDF 객체를 읽을 수 없는지 확인했다. 이 DB 검사는 Storage 객체 테이블과 경로 함수를 재현해 정책을 실행한 것이다.
