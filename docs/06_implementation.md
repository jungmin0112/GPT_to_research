# 구현 계획 — 통합형 MVP, 기능 축소 없이 순차 구현

## 공통 개발 방식

바이브 코딩이므로 작은 기능이 검증 가능한 상태에서 다음 기능을 구현한다. 사용자가 주요 기능 12개를 모두 MVP에 포함하기로 결정했다. **단계 분할은 삭제가 아닌 구현 순서**다.

각 단계 완료 시: 코드 + 마이그레이션 + 테스트 + 실제 스크린샷 또는 실행 로그(가능한 경우) + README 갱신. 비밀값이 없으면 mock 모드로 재현성 확보. 테스트를 통과하지 못하면 원인·제약을 표시하고 완료라고 주장하지 않는다.

## M0 프로젝트 기반 / 보안

- Next.js(TypeScript, App Router, Tailwind), shadcn/ui, Supabase client/server, 인증(단일 사용자), RLS.
- 프로젝트 생성/목록/선택, 기본 메인 세션 생성, 기본 3영역 UI 골격, 데스크톱/태블릿 레이아웃.
- 서버 키 보호, `.env.example`, 초기 데이터 마이그레이션, 타입 생성, 에러 처리.
- **완료**: 비인증 API 호출 거부, 사용자 프로젝트 생성/재접속 유지, DB RLS 접근 테스트, 빈 상태/오류 표시, lint/typecheck/build 통과.

## M1 GPT 대화 + 검색 + 자료 수집

- Responses API wrapper/스트림, 모델·추론 설정, 메인 세션 대화 저장, GPT 웹 검색과 인용 표시.
- 사용자 URL/PDF/텍스트 등록, 검색 자료의 폭넓은 자동 메타데이터 보관, 원문 추출과 처리 상태, 중복 처리.
- **완료**: 실제 API(키 설정 시)로 세션 대화 가능; mock으로 무키 테스트; 검색 참조로 수집된 자료의 링크/상태 확인; 제한된 URL 안전 차단.

## M2 심화 탐구 + 원문 읽기/미니 세션 + 맥락

- 분기 생성/복귀, 세션별 상태, 참조 수준/고급 출처별 설정, 참조 로그 표시.
- 원문 중앙 뷰, 문단 선택, 원문별 미니 세션, '다 읽음' Q&A 일괄 정리 패널, 메인 전달 후보 선택.
- 대화/원문/결과물에서 사용자 분기 생성, 자동 분기는 금지.
- 중앙 탭/2분할/작업 공간 복원, '현재 자료로 질문하기' 템플릿 및 ID 기반 전송.
- **완료**: 5단계 이상 분기 테스트, 원문 A·B 미니 기록 분리, 세션 전환 후 스크롤/초안 복원, 참조 조절 미래 적용 확인.

## M3 중앙 자동 갱신 + 결과물

- 10분 기준 + 가중치 + 수동 갱신/진행 상태 + 1분 체크 Cron.
- 미처리 기록의 구조화 추출, 근거 추적, 결과물 자동 생성/재구성/계층화 및 변경 이력.
- 프로젝트별 독립 결과물, 동일 노드 중복 병합, 점유율 및 근거, 충돌 검토 기록과 알림.
- **완료**: 새 변경 없으면 AI 미호출, 자동/수동 동시 요청에도 중복 없음, 충돌 해결 전 기존 본문 보존, 추적 가능한 점유율.

## M4 그래프/관리/내보내기

- React Flow 기반 두 그래프, 필터·그룹·미리보기·열기·세션 이동.
- 관리 화면 충돌 비교/해결/이력, 통합 검색, Markdown/PDF 내보내기, 활동 로그.
- **완료**: 지식 노드 -> 관련 세션으로 직접 이동; 다른 프로젝트 노드 자동 합병 없음; 원문 인용 정보 포함 PDF/Markdown.

## M5 UX 및 배포 검증

- ChatGPT형 디자인 일관성, 키보드 접근, 태블릿·모바일 기본 작동.
- E2E 전체 자료조사 플로우, 비용·권한 검증, Vercel/Supabase 환경 변수/배포 지침.
- **완료**: `docs/07_testing.md` E2E 필수 시나리오 통과, 빌드 통과, 외부 설정 미완료 시 명시적 blocker. 사용자 실제 키·DB 접근이 있어야 운영 배포 가능.

## 실패 시 처리

- 아직 설정되지 않은 OpenAI/DB는 화면에 분명한 구성 미완료 상태로 표시하고 mock 기반으로 테스트.
- 정식 배포가 불가능한 경우 허위 배포 완료 주장 금지; 사용자가 실행할 구체적인 보안 설정 단계 제공.
- API 문서가 변경되어 기능/모델 지원이 달라지면 공식 문서를 확인해 통합 방식만 보완하고 사용자 결정은 유지.

## 권장 작업 흐름

첫 Codex 턴에서는 `CODEX_START.md`에 따라 M0를 작동 가능하게 만들고, 이어 M1의 수직 단면을 시작한다. 이후 M2~M5는 같은 저장소에서 단계별로 구현한다. 다음 단계 착수 전 막힌 핵심 의사결정이 없다면 불필요한 질문을 하지 않는다.
