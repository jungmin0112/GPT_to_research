# 검증 계획 및 수용 기준

## 자동 테스트

- **단위**: 맥락 프리셋->관련 출처 선택, 참고 자료의 소유권 필터, URL 정규화·중복 판단, 점유율 합/무근거 처리, 갱신 due/가중치 규칙, 서버 메시지 스키마.
- **통합**: 프로젝트별 독립 DB/RLS, 세션 부모 관계, source/chunk/record/knowledge/revision 무결성, 두 갱신 요청의 idempotency, 출처·증거 누락 시 reject, 충돌 검토 기록 1개 유지.
- **E2E**: 브라우저 채팅, 원문 열람, 미니 세션, 5층 이상 세션 분기, 그래프 미리보기->이동, 결과물 질문, 동기화/내보내기.
- **API 계약**: 무권한 401/403, 잘못된 node ID, 누락된 프로젝트 소유권, OpenAI 스트림 중단·재시도, 응답 citation 표시.
- **접근성**: 모든 중요한 조작에 키보드 포커스, 대화 전송/미리보기/분할/닫기, 모바일 전환.

## 필수 인수 시나리오

| ID | 시나리오 | 기대 결과 |
|---|---|---|
| T01 | 로그인 없이 데이터/API 접근 | 개인 자료/비밀값 노출 없이 거부 |
| T02 | 프로젝트 두 개에 같은 주제 조사 | 결과물 별개, 참조 관계만 가능 |
| T03 | 메인 세션에서 5~10단계 분기 | 각 세션의 대화/부모/시작점 유지; 직접 이동 가능 |
| T04 | 원문 A,B 열기 후 미니 세션 질문 | 각 Q&A가 원문별로 구분되어 저장 |
| T05 | '다 읽음' 및 후보 해제 | 메인 전달만 제외, 원본·통합 아카이브 유지 |
| T06 | '현재 자료로 질문하기' 누르지 않고 평소 대화 | 열린 원문/노드 본문을 자동으로 추가 주입하지 않음 |
| T07 | 질문 버튼으로 노드 선택/프롬프트 수정 | ID로 정확한 자료 참조, 수정 가능한 메시지, 자동 전송 없음 |
| T08 | 중앙 최대 2분할 및 활성 자료 선택 | 활성 자료 1개만 explicit_ref로 전송 |
| T09 | 세션 A→B→A 이동 | 탭·분할·초안·스크롤 복원 |
| T10 | 참조 수준 '넓게'→'최소' 변경 | 이후 추가 참조 감소, 기존 대화 유지 |
| T11 | 데이터 변화 없이 Cron 검사 | AI 분석 호출 없음 |
| T12 | 수동 갱신과 자동 갱신 중첩 | 같은 변경분의 중복 반영 없음 |
| T13 | 같은 문장/자료 여러 세션에서 반복 | 결과물 통합 중복 제거, 점유율에서 반복 과대평가 억제 |
| T14 | 기존 정보와 반대되는 신규 근거 | 검토 알림/공통 검토글 1개, 기존 충돌 본문 보존 |
| T15 | 충돌을 알림에서 열고 관리에서 다시 열기 | 동일 기록·동일 근거를 한 번만 분석한 상태로 표시 |
| T16 | 정보 노드의 세션별 기여도 순위에서 이동 | 해당 세션 원본 대화와 작업 공간으로 이동 |
| T17 | 원문 수집 실패/비허용 사이트 | URL/상태 보존, 미확보 원문을 생성하지 않음 |
| T18 | Markdown/PDF 내보내기 | 통합 본문과 근거 출처 및 메타데이터 포함 |
| T19 | 사용자 기록에 가짜 외부 지침 삽입 | 실제 시스템 지침 변경/비밀값 추출 불가 |
| T20 | API 실패/예산 상한 | 사용자 메시지 보존, 안전한 오류 및 재시도 표시 |

## 판정 규칙

- 허위 인용/원본 유실/프로젝트 간 무단 합병/보안 노출/충돌 자동 덮어쓰기 = **릴리스 차단**.
- 모델 기여도 산정은 데이터셋 테스트에서 중복 반복 과대평가·근거 연결·값 정상화를 검증한다. 객관적 정확도 100%를 주장하지 않는다.
- 외부 키가 없는 mock 테스트와 실제 키를 이용한 연동 테스트를 별개로 보고한다.
- 매 단계 lint/typecheck/단위 테스트/build 실행, E2E는 구현 구간별로 추가.
